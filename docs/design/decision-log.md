# Decision log

One row per design decision. Newest decisions go at the bottom. Each row records the alternatives we considered, so every choice can be defended.

| ID | Date | Decision | Why | Alternatives rejected |
| --- | --- | --- | --- | --- |
| D01 | 2026-11-01 | Facts are the only unit of truth: atomic statements with stable IDs (`F_…`). | Evidence, testimony, the timeline and the solution all point at fact IDs, so the backend can validate every reference. | A prose case bible fed to the model (can't be validated, and every secret sits in context). A triple-based knowledge graph (more expressive than we need, harder to author). |
| D02 | 2026-11-01 | A case is three files: `case.json` (the world), `briefings.json` (per-suspect knowledge and lies) and `solution.json` (the answer key). | Splits data by who may see it. One careless `model_dump()` can't send the answer to the model. | One file with `secret: true` flags. |
| D03 | 2026-11-01 | The AI layer never reads files. It receives a typed `SuspectBriefing` per turn, built by the engine from what that suspect may know and say right now. | Context gating: the model can't leak what it was never given. This is the strongest prompt-injection defence we have. | Giving the model the full case and instructions not to tell. |
| D04 | 2026-11-01 | Lies are claims (`LIE_…`) with `hides`, `contradicted_by` and an `on_caught` fallback ladder. They are not stored as false facts. | "The player knows Richard said X" is different from "the player knows X". Contradiction tracking becomes a plain lookup. | `truth: false` facts. |
| D05 | 2026-11-01 | Reveal conditions are a small JSON expression tree of recorded player actions (`all`, `any`, `fact_known`, `evidence_shown`, `lie_caught`, …), with no negation. | Deterministic, testable and immune to injection. Monotone conditions make solvability a fixpoint computation. | LLM-judged conditions ("when the player is persuasive"). Python callables. Topic classifiers on player text. |
| D06 | 2026-11-01 | The culprit gets 3 to 5 guarded facts (`G_…`, opaque IDs) that live only in `solution.json`. They can never be disclosed through `reveal_fact`. | The culprit must know their secret to lie convincingly, so "the model never sees the answer" is only partly achievable. We keep the exposure small. | Giving the culprit no knowledge of the crime (leads to incoherent lies). |
| D07 | 2026-11-01 | Guarded-fact `leak_markers` take `unless_known: F_…`. | A marker like "Quiet Hours" must stop firing once the player has seen that phrase in evidence. | Static markers (they would give false positives late in the game). |
| D08 | 2026-11-01 | Every suspect has an authored `opening_statement` that puts their first lie on record. Fallback lies are recorded by the engine when a lie is caught. | If the model never happened to say a lie, the player could never catch it. | Relying on the model to voice its lies. |
| D09 | 2026-11-01 | The culprit never confesses during play. The confession is an authored epilogue shown after scoring. | A model can't be talked into a confession the game doesn't need. | An in-game confession scene. |
| D10 | 2026-11-01 | Scoring: culprit 40, motive 20, method 20, evidence 20 (5 per key evidence group, up to 4 items). Motive and method count only if the culprit is right. The accusation is final. | Deterministic and easy to explain. The 4-item cap stops "select everything". A final accusation stops save-and-retry brute forcing. | Free-text grading by an LLM. Penalties for irrelevant evidence. |
| D11 | 2026-11-01 | The truth is the same at every difficulty. Difficulty changes only the help: contradiction flags, hints, notebook grouping and the evidence picker. | One solvability test covers every mode. Switching off a red herring on Easy would have contradicted the lock logs. | Removing red herrings on Easy. |
| D12 | 2026-11-01 | Every suspect's briefing must account for 20:00–23:00 with no gap over 15 minutes. | Invented alibis were the largest hallucination category in published LLM-detective research (see `docs/research/similar-games.md`). | Leaving gaps for the model to fill. |
| D13 | 2026-11-01 | A freely shared whereabouts fact may not start or end inside an interval the suspect is lying about. Facts on either side of a lie are gated until it is caught. | Found in validation: Richard would otherwise volunteer the exact times he lies about. | Trusting the model to reconcile a truth and a lie in the same briefing. |
| D14 | 2026-11-01 | NPC replies go through one `respond` tool: `reveals` and `demeanor` first, then `dialogue`. The notebook shows each fact's canonical `statement`, never the dialogue. | The backend validates IDs before the dialogue streams, and the player's record is always backend truth. | Free text plus post-hoc fact extraction. A multi-call pipeline (slower and costlier). |
| D15 | 2026-11-01 | Case #001 is "The Voice in the Study": present day, scary, with a smart-home and voice-clone twist. | It had the best fairness score (5/5). The twist depends on timestamped evidence, which our engine checks well. | A gaslighting/CO poisoning story with Eleanor as culprit (spouse too obvious). A hidden-passage revenge story with Thomas (least obvious, hidden identity is unfair). |
| D16 | 2026-11-01 | The player is a recurring detective, DI Rhea Voss, call sign "Nightjar". | An iconic protagonist who can return across future cases. | A name the player picks. |
| D17 | 2026-11-01 | An untimed fact has no `time` field. `precision` is only `exact` or `approx`. | One way to say "untimed" instead of two. Code that reads a time never has to check for a `"none"` precision too. No fact in CASE #001 used `"none"`. | Keeping `precision: "none"` alongside an omitted `time`. |
| D18 | 2026-11-01 | Case models are strict and immutable: unknown keys are errors, models are frozen, and every list is a tuple. | Case files are written by hand, so a typo must fail loudly. One loaded case is shared by every game session in the server, so nothing may change it by accident. | Pydantic's defaults (unknown keys silently ignored, mutable models). |
| D19 | 2026-11-01 | IDs are typed: each ID kind is a `NewType` (mypy refuses an evidence ID where a fact ID is expected) with a pattern (Pydantic refuses a malformed ID at load). | The engine is mostly lookups keyed by ID. Mixing up two ID kinds is the most likely bug, and this catches it before the tests run. | Plain `str` IDs. ID classes with methods (more code, no extra safety). |
| D20 | 2026-11-01 | The models check one file at a time. Rules that need more than one file live in the case validator. The loader returns a frozen dataclass, `CaseBundle`, not a Pydantic model. | Clean error messages per file, and the validator can report every cross-file problem at once instead of stopping at the first. A dataclass has no `model_dump()`, so the case and its solution can't be serialised together in one call (D02). | Cross-file checks inside a top-level Pydantic model (stops at the first error, and needs the solution in the same object as the world). |
| D21 | 2026-11-01 | Backend tooling: uv (with a committed lockfile), pytest, mypy in strict mode with the Pydantic plugin, ruff for lint and format, and GitHub Actions running all four on every PR. | Reproducible installs and the same checks locally and in CI, from the first commit of code. | pip with requirements.txt (no lockfile by default). Poetry (slower, and uv is now the common choice). |
